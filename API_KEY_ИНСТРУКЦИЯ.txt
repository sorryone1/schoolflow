ШКОЛА+ V6 — КУДА ВСТАВИТЬ КЛЮЧ ИИ
=================================

1. Откройте папку backend.
2. Скопируйте файл .env.example в новый файл .env (именно с точкой спереди).
   Файл .env.example менять не обязательно.
3. Откройте backend/.env любым текстовым редактором.
4. Заполните переменные (ПРИМЕР, НЕ РЕАЛЬНЫЙ КЛЮЧ):

DARKAPI_API_KEY=вставьте_свой_секретный_ключ_сюда
DARKAPI_BASE_URL=https://darkapi.shop/v1
DARKAPI_MODEL=название_вашей_модели_с_поддержкой_изображений
SCHOOL_PLUS_SECRET=сгенерируйте_случайный_длинный_секрет
DEMO_MODE=1

5. Перезапустите сервер через start.bat либо start_lan.bat.
6. Войдите как teacher / 1234 в демо-режиме, создайте заявку
   с фотографией и проверьте карточку ШКОЛА+ AI.

ПРОВАЙДЕР:
В исходном проекте настроен OpenAI-совместимый шлюз DarkAPI.
Уточните у провайдера точное название модели, доступность API
и поддержку изображений. Если используете официальный OpenAI API,
укажите вместо этого:
OPENAI_API_KEY=ваш_ключ
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=доступная_мультимодальная_модель
(и оставьте DARKAPI_API_KEY пустым).

БЕЗОПАСНОСТЬ:
- Никогда не вставляйте ключ в frontend/assets/*.js или index.html.
- Никогда не отправляйте .env в GitHub, чат или архив для публикации.
- Файл backend/.env уже исключён из git через .gitignore.
- Для реального внедрения: DEMO_MODE=0, HTTPS, смените все
  демонстрационные пароли, используйте защищённые HttpOnly cookies,
  внешний rate limiter, аудит доступа и правила обработки фото детей.
- sessionStorage уменьшает постоянное хранение токена, но НЕ
  защищает от XSS; переход на HttpOnly cookies — следующий этап.

ИИ:
- Диагностика и уточняющий вопрос создаются при загрузке нового фото.
- Ответ на уточняющий вопрос сохраняется в заявке, но пока не
  передаётся автоматически на повторную диагностику модели.
- Повторные поломки считаются по правилам (2+ заявки одной категории
  в одном кабинете за 90 дней), это не машинный прогноз.
- При отсутствии ключа заявка продолжит создаваться без анализа фото.
